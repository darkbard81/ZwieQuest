# 수동 전투 스킬과 데이터 목록

`data-templates/skills.json`이 추가 가능한 스킬의 기준 목록이다. 서버 시작 때 읽고 검증하며, 변경 후 서버를 재시작해야 반영된다. JSON 안에 실행 코드나 수식을 문자열로 넣지 않는다.

## 관리 필드

| 필드 | 의미 |
| --- | --- |
| `schemaVersion` | 현재 구조 버전 2 |
| `maxEquipped` | 장착 슬롯 수. 현재 규칙은 6으로 고정 |
| `skills[].id` | 저장·쿨다운 식별자. 영문 소문자·숫자·하이픈. 출시 후 변경하지 않는다 |
| `name`, `icon`, `description` | 표시 이름, 문자/이모지 아이콘, 설명 |
| `enabled` | 활성 여부. false면 보유 기록은 남고 사용·신규 장착·기본 지급이 중단된다 |
| `grantOnCreate` | 기본 지급 여부. 기존 캐릭터도 저장을 불러올 때 미지급 항목을 한 번 받는다 |
| `equipByDefault` | 처음 지급할 때 첫 빈 슬롯에 장착. 이미 해제한 스킬은 재장착하지 않는다 |
| `useContexts` | 사용 가능 상황 배열: `combat`(전투), `nonCombat`(비전투). 양쪽 허용도 표현 가능 |
| `activationMode` | `direct`(직접 사용), `toggle`(ON/OFF 유지 효과) |
| `perBattleLimit` | 전투당 성공 사용 횟수 제한. 양의 정수 또는 `null`(제한 없음). 비전투 사용에는 적용하지 않음 |
| `toggleConsumesTurn` | 유지형 ON/OFF 전환의 턴 사용권 정책. `true`/`false` 또는 `null`(미정, 실행 차단) |
| `effect.amount` | 유지형 명중 보정의 실제 ACC 가산값. 1은 명중 수치 +1이며 +1%가 아님 |
| `effect.weaponCategories` | 유지형 효과를 적용할 무기 카테고리 ID 배열. 예: `["dagger"]` |
| `effect.type` | 현재 지원 효과는 `heal`(직접 회복), `accuracyBonus`(조건부 유지 명중 보정). 새로운 효과 종류는 서버 구현·검증을 먼저 추가해야 한다 |
| `effect.maxHpRate` | 최대 HP 대비 기본 회복 비율. 0.1 = 10% |
| `effect.intelligenceRate` | 유효 INT 1당 최대 HP 대비 회복 비율 가산. 0.05 = +5%p (기본 비율과 합산) |
| `cooldown.baseMs` | 기본 재사용 대기 시간(밀리초) |
| `cooldown.dexterityReductionRate` | DEX 1당 기본 대기 시간의 감소율 |
| `cooldown.minimumMs` | 음수 방지 하한. 회복은 0ms |

같은 heal 효과의 이름·아이콘·수치가 다른 스킬은 고유 ID로 항목을 추가할 수 있다. `grantOnCreate:false`인 스킬은 목록에만 등록되며, 향후 습득 경로를 별도로 연결한다. 기본 지급으로 추가하면 새 캐릭터와 기존 캐릭터 모두 최초 1회 지급된다. 기존 ID를 삭제하기보다는 `enabled:false`를 사용한다. 정의가 누락된 보유 스킬은 삭제하지 않고 사용 불가로 표시한다.

최소 변경 예: 회복의 재사용 시간을 15초로 바꾸려면 `cooldown.baseMs`만 `15000`으로 수정한다. 이미 진행 중인 쿨다운은 그대로 끝나고 다음 사용부터 새 수치를 적용한다.

## 회복 규칙

- 모든 캐릭터가 개별적으로 기본 1개 습득 및 1번 슬롯 장착. 스킬은 판매할 수 없다.
- 회복은 `useContexts:["combat"]`, `activationMode:"direct"`, `perBattleLimit:2`이다. 전투당 최대 2회, 모든 직접 사용 스킬을 합쳐 자기 턴당 1개라는 제한을 동시에 적용한다.
- 실제 회복량: `min(최대HP − 현재HP, max(0, floor(최대HP × (0.10 + 유효INT × 0.05))))`.
- INT 0은 최대 HP의 10%, INT 4는 최대 HP의 30%를 회복한다.
- 재사용 시간: `max(0, round(20000 × (1 − 유효DEX × 0.05)))` 밀리초.
- 장비를 포함한 유효 능력치를 사용 시점에 계산한다. 음수 DEX는 대기 시간을 늘린다. 회복량은 음수가 되지 않으며 0이면 사용을 거절한다.
- 현재 정상 장비 범위에서 DEX는 −2~4, 쿨다운은 22~16초다. 미래에 DEX가 20 이상이면 0초가 되지만 턴당 1회 제한은 유지된다.
- 최대 HP 상태에서는 사용하지 않고 턴 사용권·쿨다운·전투별 횟수도 소비하지 않는다.
- 전투 중 자기 턴에만 수동으로 사용한다. AP 소모, 자동 사용, 공격 횟수·공격 타이머 초기화는 없다.
- 직접 사용 스킬은 개수·종류와 무관하게 자기 턴당 1개만 사용한다. ON/OFF 전환은 이 제한에서 제외한다. 요청의 전투 ID·라운드도 검사해 지연 요청이 다음 턴에서 실행되지 않게 한다.
- 장착 중인 스킬의 쿨다운은 시계방향으로 음영이 걷히며 초 단위 숫자로 표시된다. 사용 불가·빈 슬롯·이번 턴 사용 상태는 별도로 표시한다. 버튼과 가방 설명에 남은 횟수(2/2, 1/2, 0/2)를 표시하며 0/2는 소진 상태로 비활성화한다.

## 유지형 예시와 ON/OFF 정책

`dagger-mastery`는 단검숙련 검증용 예시로 등록했으며 `enabled:false`, `grantOnCreate:false`, `equipByDefault:false`다. 기존·신규 캐릭터에게 지급하지 않는다. 효과 계산기는 전투 중 장착된 스킬이 ON이고, 현재 무기의 `templateId`가 `dagger`일 때만 ACC +1을 더한다. OFF·다른 무기·스킬 미장착·전투 외에는 더하지 않는다. 같은 템플릿의 복수 사본도 1회만 적용하며 기본 능력치에 덮어쓰거나 매 틱 누적하지 않는다. DEF·REF·FOR·WIL 계산과 무기별 명중 판정 대상은 그대로 유지한다.

사용자는 ON/OFF 전환을 턴당 스킬 1개 제한에서 제외하도록 확정했다. 단검숙련 예시의 `toggleConsumesTurn:false`에 반영했으며, 이미 직접 사용 스킬을 쓴 자기 턴에도 ON/OFF를 전환할 수 있다. 전환은 기존 `battle.skillUsed`를 소비하거나 초기화하지 않고 AP도 소모하지 않는다. 미정 값을 명시한 다른 미래 항목은 `null`이면 실행을 차단한다.

현재 유지형 구현은 자기 턴에 상태를 전환한다. ON 활성화는 성공 사용으로 기록하며 전투당 제한과 쿨다운을 적용한다. OFF는 효과를 해제하므로 활성화 횟수나 쿨다운을 소비하지 않는다. 턴 사용권의 소비 여부는 ON/OFF 모두 확정된 `toggleConsumesTurn` 값을 따른다. 단검 예시는 `perBattleLimit:null`이다. 전투가 끝나면 효과가 사라지고 다음 전투는 OFF로 시작한다.

## 저장 및 이관

습득 스킬은 각 `characters[]`의 `skills` 배열에 있는 `slot:skill` 항목이다. 공용 장비 인벤토리에 저장하지 않는다. 가방 UI는 공용 장비와 현재 캐릭터의 스킬만 합쳐 표시한다. 장착은 별도의 6칸 `skillSlots`, 재사용 시간은 템플릿 ID별 `skillCooldowns`의 `startedAt`·`readyAt`·`durationMs`, 최초 지급 기록은 `skillGrants`에 보관한다. 스킬은 장비 능력치 합산 대상이 아니다. 소지 장비만 공용이며 스킬·장착 슬롯·최초 지급 기록·쿨다운은 캐릭터 사이에 공유하지 않는다. 다른 캐릭터가 가진 스킬 ID를 요청하면 거절한다.

턴당 사용 여부는 `battle.skillUsed`, 전투별 성공 사용 횟수는 템플릿 ID별 `battle.skillUseCounts`, ON/OFF 상태는 `battle.skillToggles`로 서버에서 관리한다. 횟수는 라운드 변경이나 재장착으로 초기화하지 않고 새 전투 생성 시에만 새 객체로 시작한다. DB에 쿨다운과 함께 저장되어 재접속·서버 재시작·장착 해제/재장착으로 초기화되지 않는다. 쿨다운은 실제 서버 시각을 사용하므로 오프라인 2배 진행과 무관하다. 서버가 정지한 동안에도 실제 대기 시간은 흐른다.

횟수 필드가 없는 진행 중 전투를 처음 읽을 때는 최근 전투 시작 로그 이후의 성공한 회복 로그를 집계한다. 시작 로그가 남아 있지 않으면 추가 사용권을 임의 지급하지 않도록 해당 전투의 회복 2회를 소진 처리한다. 이미 횟수가 저장된 전투는 로그로 다시 계산하지 않는다.

기존 전술·예약 AP·버프는 제거한다. 진행 중인 전투의 현재 HP·몬스터·선공 순서·행동자·남은 AP·공격 횟수는 보존하며 행동을 재실행하지 않는다. 이미 소비된 전술 AP는 소급 환급하지 않고 다음 턴부터 일반 공격 3 AP를 적용한다. DB 테이블 구조와 계정은 바꾸지 않는다.

## 자동회복

캐릭터 생성 시 초기 HP는 최대치다. 반복 모험에서는 여관의 대기 시간이 끝나 **여행을 시작할 때** 최대 HP로 회복한다. 귀환 이동 완료·전투 승리·보물·레벨 상승·지역 이동·캐릭터 선택·장비 교체·관리자 지도 재생성은 자동회복하지 않는다. 최대 HP가 줄어들면 현재 HP만 새 상한까지 제한한다.

## 검증

`node --test tests/skill-limits.test.js tests/skills.test.js tests/skills-http.test.js`로 JSON 검증, 최초 지급, 6칸 장착, 유효 능력치 공식, 자동회복 제거, 전투당 2회, 턴·쿨다운·중복 요청·재시작 보존, 비전투/무제한 표현, 단검 조건부 ON/OFF 명중 +1을 확인한다. HTTP 테스트는 임시 DB에만 테스트 계정을 만든다.
