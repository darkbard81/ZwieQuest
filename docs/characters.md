# 캐릭터 시스템 — 이슈 #4

클래스는 제거했다. 외형 6종의 기존 자산 ID는 유지하되 능력치/성장과 연결하지 않는다. 로그인과 캐릭터 생성은 분리한다.

## 계정과 캐릭터

- 여관에서 이름(공백 제거 후 1~20자, 제어문자 금지)과 외형을 골라 최대 3명 생성한다. 이름은 중복 가능하지만 서버 UUID로 소유권을 구분한다.
- 선택된 한 캐릭터만 출전한다. 캐릭터가 0명이면 자동 출발하지 않는다.
- 캐릭터별: 이름·외형·레벨·XP·현재 HP·6 능력치 투자값·장비 참조·습득 스킬·장착 스킬·쿨다운·스킬 지급 기록.
- 계정 공용: 실제 장비 인벤토리·금화·지도·탐험·체크포인트·경로·모험 기록.
- 아이템 하나는 한 캐릭터만 장착한다. 다른 캐릭터에게 넘기려면 여관에서 소유 캐릭터를 선택해 해제한 뒤 바꿔 장착한다. 누구든 장착 중인 장비는 개별/일괄 판매에서 제외한다.
- 여관의 은퇴는 해당 캐릭터의 성장·스킬·장착 참조만 제거한다. 장착하던 장비는 공용 가방에 남고 금화·경로·지도도 유지한다. 이름 확인 후 삭제하며 마지막 캐릭터 은퇴 시 출발을 멈춘다.

## 생성과 성장

초기 레벨 1, XP 0, STR/CON/DEX/PER/INT/RES 투자값 모두 0. 일반 단검과 일반 가죽갑옷(특수 옵션 없음)을 지급하고 장착한다. 부적은 없다. 회복 스킬은 캐릭터마다 독립된 ID로 습득/1번 슬롯 장착한다.

- 누적 포인트 `10 + floor(level / 2)`.
- 미사용 포인트 `누적 포인트 − 6 투자값 합계`. 캐릭터의 레벨/투자값으로 산출하며 별도 지급 이벤트를 반복 실행하지 않는다.
- 모험 정보의 능력치를 클릭하면 서버가 해당 투자값을 정확히 1 올린다. 클라이언트가 보낸 수량을 사용하지 않는다. 투자 취소/재분배 기능은 없다.
- 미사용 포인트를 남겨둔 출발을 허용한다. 모험 중에도 포인트를 배분할 수 있다.
- 투자값 + 장비 보정이 유효 능력치다. 가죽갑옷 DEX −1 때문에 미투자 캐릭터의 표시 DEX는 −1이다.
- 최대 HP `10 + 5 × (level − 1) + 5 × 유효 CON + 장비 HP`.
- ACC 및 DEF/REF/FOR/WIL의 기본값은 각각 10. 관련 능력치·장비 보정 및 `floor((level−1)/3)` 레벨 보너스는 별도로 합산한다. 클래스 숙련은 없다.
- 생성 시 공식의 최대 HP로 시작하고 여관 출발 시 선택 캐릭터만 최대 HP로 회복한다. 능력치 투자·장비 교체·레벨 상승·캐릭터 선택은 현재 HP를 채우지 않는다.
- XP는 출전 캐릭터에게만 지급한다. 금화·드롭은 계정 공용으로 누적된다.

## 여관 시간

기존 자동 모험과 온라인/오프라인 배속은 유지한다. 최초 계정과 캐릭터 생성 뒤에는 출발 일시정지 상태다. 관리 화면을 열면 서버에 `PAUSE_HOME`을 확정한 후 편집한다. 이름/외형 설정 중 15초가 지나거나 새로고침해도 출발하지 않는다.

관리 창을 닫으면 보유 캐릭터 최대 3명이 모험의 창에 모두 Idle로 표시된다. 캐릭터 위에 포인터를 올리거나 키보드로 초점을 맞추면 출발 대상을 표시하고, 클릭·터치·Enter/Space로 확정하면 해당 캐릭터를 선택한 뒤 즉시 출발한다. 여관에는 `캐릭터 관리` 버튼만 남긴다. 관리 화면의 별도 출전 선택 버튼은 제거한다. 일반 귀환은 선택된 캐릭터를 유지해 다음 자동 모험으로 이어진다. 캐릭터 선택 시 다음 출발의 카운트다운을 15초로 갱신한다. 다른 탭에서 출발하면 열린 관리 화면은 닫히며 HOME 전용 변경은 서버가 거절한다.

## 저장·API와 이관

`characterVersion:1`, `characters[]`, `activeCharacterId`가 저장 원본이다. 게임 상태에 성장/장비/HP를 중복 저장하지 않는다. API의 최상위 `level/xp/hp/equipment/skillSlots/...`는 선택된 캐릭터의 표시용 투영이며 `inventory`는 공용 장비 + 그 캐릭터의 습득 스킬만 제공한다. `equipmentUsers`는 캐릭터 UUID 목록이다.

명령은 `CREATE_CHARACTER`, `SELECT_CHARACTER`, `RETIRE_CHARACTER`, `ALLOCATE_STAT`, `PAUSE_HOME`, `RESUME_HOME`, `DEPART`. 개인 장착/스킬/배분/출발 요청에는 현재 `characterId`가 필요하다. 다른 계정 ID, 이전 탭의 선택 ID, 4번째 캐릭터, 잘못된 능력치, 잔여 포인트 부족을 서버에서 거절한다. SQLite 트랜잭션과 요청 ID 중복 방지는 유지한다.

기존 클래스 저장본은 최초 1회 다음과 같이 이전한다.

1. 현재 클래스는 현재 외형 이름의 캐릭터로, 실제 보관된 비활성 클래스는 `기존 전사`/`기존 마법사`로 이전한다. UUID를 생성하고 해당 레벨·XP·장비를 보존한다.
2. 클래스 기본 능력치는 제거하고 투자값 0 및 보존된 레벨의 전체 포인트 예산을 부여한다. 기존에 자유 투자 시스템이 없었으므로 투자 이력은 만들지 않는다.
3. 공용 장비·금화·지도·경로·체크포인트를 보존한다. 중복 장착 참조가 있으면 현재 캐릭터의 장착을 우선하고 비활성 캐릭터의 중복 참조만 해제한다. 아이템은 삭제/복제하지 않는다.
4. 기존 공용 스킬과 쿨다운은 현재 캐릭터에 이전한다. 비활성 캐릭터에는 독립된 기본 회복을 지급한다. 기존 스킬은 공용 장비 목록에서 개인 목록으로 이동한다.
5. 현재 HP는 새 최대 HP를 넘을 때만 제한한다. 구형 비활성 클래스에는 HP 저장값이 없으므로 새 공식의 최대 HP로 초기화한다.
6. 현재 지도 위치·진행 단계·타이머·몬스터·선공·AP·공격 횟수·회복 사용 횟수는 보존하며 공격/보상을 재실행하지 않는다. 이후 재시작에서는 UUID/아이템/포인트를 다시 생성하지 않는다.

배포 전 SQLite 온라인 백업과 복사본 이관 검증을 수행한다. 관리자도 캐릭터를 자동 생성하지 않으며 기존 지도 공개 권한은 유지한다. 관리자 계정 초기화는 캐릭터/소지품/금화/진행을 비우지만 인증·권한·지도 구조는 유지한다.

## 검증

`tests/characters.test.js`, `tests/server.test.js`가 생성·소유권·투자·다중 탭·은퇴·저장·이관을 검증한다. 기존 전투/회복/장비/지도/관리자 테스트는 캐릭터 모델로 갱신했다. 브라우저 검증은 별도 임시 서버/계정/DB에서 수행한다.
